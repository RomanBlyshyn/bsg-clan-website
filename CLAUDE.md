# B.S.G.REC. Clan — сайт + адмінка

Сайт хіп-хоп колективу B.S.G. (Big Shaark Gang, Вроцлав) і Studio Kush 37.
Живий: https://bsgclan.com (Netlify), база — Supabase, проєкт `xfimviivrmqztxnjczok`.

## Структура
- `site/` — статичний сайт, без збірки. Деплой: власник перетягує папку `site/` у Netlify → Deploys.
  - `config.js` — Supabase URL + anon key (публічний, його можна комітити). Порожньо → сайт бере дані з `data.js`.
  - `app.js` — публічний сайт, форма заявки (`FIELD_RULES`), блок `CREDIT`.
  - `admin.html` / `admin.js` — адмінка, ролі owner/admin/user.
  - `i18n.js` — мови uk / ru / pl / en.
- `supabase/` — SQL, який запускається вручну в SQL Editor (або через Supabase MCP) по порядку: `schema.sql`, `02-telegram-and-validation.sql`.
- `АДМІНКА.md` — інструкція з налаштування для людей.

## Правила
- `CREDIT` в `app.js` змінює тільки власник. Не переносити його в `data.js`, базу чи адмінку.
- Будь-яка форма: при помилці — зрозуміле «не надіслано, спробуйте ще раз», введені дані не зникають; валідація і на клієнті, і в базі (RLS / check).
- Правила валідації заявок мають збігатися в `app.js` (`FIELD_RULES`) і в RLS-політиці `anyone can apply`.
- Секрети (токен Telegram-бота, chat_id, service_role key) — тільки в Supabase Vault, ніколи у файлах.
- Зміни в базі — новим нумерованим файлом у `supabase/` (`03-...sql`), а не правкою старих, які вже запущені.
- Тексти сайту чотирма мовами; польський потребує перевірки носієм.
- Дизайн: жовтий/чорний, мінімалістичний, але живий.
